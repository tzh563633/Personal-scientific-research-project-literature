# P2 计划与验收标准

## P2 目标

P2 的目标是把 P1 已完成的“代码项目只读检查能力”做成交付闭环：用户上传或登记代码项目后，可以在平台内安全地浏览有限文件内容、生成项目检查 Markdown 报告，并用自动化与容器级验收证明这些能力不执行项目代码、不越界读取、不污染本地科研数据。

P2 不进入真实漏洞库联网扫描，不安装上传项目依赖，不执行上传项目脚本，不打开公网暴露或 HTTPS 反向代理。P2 结束后，所有项目代码和相关文档会重新提交并推送到 GitHub。

## P2 交付内容

1. 受限文本文件预览
   - 新增只读文件预览 API。
   - 只允许项目目录内相对路径。
   - 跳过二进制文件、符号链接和超大文件。
   - 预览内容限制为固定大小，超限时标记 `truncated`。
   - 对常见密钥形态做轻量脱敏，避免前端直接展示疑似 secret。

2. 项目检查 Markdown 报告
   - 新增项目检查报告 API。
   - 报告汇总 Git 状态、最近提交、依赖风险、许可证/来源、文件树和主要警告。
   - 报告为 Markdown 字符串，便于用户保存、复制、归档。
   - 报告生成仍然只读，不执行项目代码。

3. 前端代码管理视图增强
   - 在代码检查抽屉中加入文件预览入口。
   - 加入项目检查报告页签。
   - 保持现有 Git 状态、提交详情、diff、依赖风险、文件树页签。

4. 集成测试与安全测试
   - 覆盖上传压缩包后的项目检查流程。
   - 覆盖路径穿越、二进制预览拒绝、预览截断、疑似密钥脱敏。
   - 覆盖项目检查报告的 Git/依赖/文件树汇总。

5. 文档与最终验收报告
   - 本计划文档作为 P2 启动文件。
   - P2 结束时新增 P2 验收报告。
   - 更新 README/API/P1/P2 相关说明。

## 验收标准

P2 最终必须满足以下验收项：

1. 自动化测试
   - `pytest -q` 全部通过。
   - `python -m compileall -q backend agent tests` 通过。
   - `docker compose config --quiet` 通过。

2. 前端构建
   - `npm run build` 成功。
   - Docker frontend 镜像可构建。

3. 容器运行
   - `docker compose up -d --build backend frontend` 成功。
   - backend healthcheck 为 healthy。
   - `/health` 返回 `ok`。

4. P2 runtime 临时项目验收
   - 创建并自动清理一个临时代码项目。
   - 文件树能列出安全目录并跳过 `node_modules` 等重目录。
   - 文本预览能返回内容，疑似密钥被脱敏。
   - 大文本预览返回 `truncated=true`。
   - 二进制文件预览被拒绝。
   - 项目检查 Markdown 报告包含 Git、依赖风险、文件树和预览安全说明。

5. 安全边界
   - 不执行上传代码。
   - 不安装上传项目依赖。
   - 不联网查询漏洞库。
   - 不读取项目目录外路径。
   - 不把 `.env`、真实文献、备份、解析产物或临时验收项目提交到 GitHub。

6. GitHub 上交
   - P2 代码、测试和文档提交到本地 Git。
   - P2 成果推送到 `https://github.com/tzh563633/Personal-scientific-research-project-literature.git` 的 `main` 分支。

## P2 完成边界

P2 完成后，平台会具备可用的只读代码项目检查闭环，但以下内容保留到后续阶段：

1. 真实 CVE/OSV 联网漏洞扫描。
2. 依赖许可证全文解析和合规策略库。
3. 代码语义分析、调用图、执行路径分析。
4. 多用户权限隔离的细粒度项目授权。
5. 公网 HTTPS 部署和反向代理。
