# P4 产品需求与架构梳理

## 1. 产品定位

P4 是从“功能模块平台”走向“个人科研控制台”的架构改造阶段。它不追求一次性完成所有深度分析能力，而是先把最终目标的四个核心页面、桌面入口、跨模块数据流和用户操作路径固定下来，为 P5/P6/P7 的工程实现打地基。

最终平台应让用户从桌面图标进入控制平台，并在控制平台内围绕四个页面完成科研工作：

1. 实时追踪期刊论文更新情况。
2. 导入指定文件夹后，对其中所有 PDF 文献进行分析并提炼 Excel。
3. 在页面顶部填写 DeepSeek API Key，结合用户大纲和指定 Excel 生成文献综述。
4. 管理代码分支，并保存研究方法、研究工具、分析流程和可复用经验。

## 2. P4 阶段目标

P4 的目标是完成控制台级别的信息架构和工程骨架：

1. 桌面入口
   - 提供 Windows 桌面快捷方式或启动器脚本。
   - 用户点击后自动启动本地服务，打开控制平台首页。
   - 启动器需要检查 Docker、端口、服务健康状态，并给出清晰错误提示。

2. 四页面导航框架
   - 将现有多个模块重组为四个核心页面。
   - 保留已有 P0-P3 能力，但按最终目标重新命名和归类。
   - 页面入口要面向科研工作流，而不是面向技术模块。

3. 控制台首页与状态总览
   - 首页呈现四个核心页面的入口卡片、最近任务、最近材料和系统状态。
   - 用户能从首页快速进入“期刊追踪”“文件夹分析”“综述撰写”“研究资产管理”。

4. 跨页面数据流
   - 明确“期刊论文 -> 文献库 -> Excel -> 综述 -> 研究资产”的数据流。
   - 为后续阶段预留统一的任务状态、材料索引和结果文件访问方式。

5. 产品文案与术语统一
   - 统一页面名称、按钮名称、状态名称和结果名称。
   - 消除当前“文献、期刊、代码、远程指令、系统配置”等偏工程模块的割裂感。

## 3. P4 不做的内容

P4 不应把后续阶段的深功能混进来：

1. 不在 P4 内完成所有 PDF 批量分析准确率优化。
2. 不在 P4 内完成 DeepSeek 综述生成的最终质量打磨。
3. 不在 P4 内完成完整研究方法/工具资产库的高级检索。
4. 不在 P4 内做公网部署、HTTPS、多人权限隔离。
5. 不自动读取用户全盘文件，只使用用户显式选择或配置的文件夹。

## 4. 四个核心页面设计

### 4.1 期刊追踪页面

产品目标：

让用户持续看到关注期刊和关键词的最新论文更新，并知道哪些内容值得进一步下载、阅读或纳入综述。

页面应包含：

- 期刊源列表：名称、RSS/网页地址、启用状态、最近检查时间。
- 关键词策略：包含词、排除词、语言、主题方向。
- 最新论文列表：标题、作者、期刊、发布时间、链接、匹配关键词、提醒状态。
- 操作：刷新、启用/停用源、添加关键词、查看匹配原因、加入待分析材料。

P4 只需完成页面结构和对既有期刊监控能力的整合；实时更新细节和更强抓取策略可放入 P5。

### 4.2 文件夹文献分析页面

产品目标：

用户指定一个文件夹后，平台识别其中所有 PDF 文献，批量解析并生成 Excel 表格。

页面应包含：

- 文件夹选择/登记区域：显示当前目标文件夹、可用文件数、最近扫描时间。
- PDF 列表：文件名、大小、修改时间、解析状态、错误信息、是否已入库。
- 批量分析任务：开始分析、查看任务进度、失败重试。
- Excel 输出区：最新 Excel 文件、生成时间、下载/打开入口、人工修改保护状态。

重要产品边界：

- Web 浏览器不能直接任意读取本机路径，必须通过本地 Agent 或桌面启动器授权后的后端能力完成。
- P4 应先定义“文件夹登记 + Agent 扫描 + 后端任务”的产品流，P5 再完善批量解析与 Excel 质量。

### 4.3 DeepSeek 综述撰写页面

产品目标：

用户在页面顶部直接填写 DeepSeek API Key，提交综述大纲和指定 Excel，平台生成对应文献综述。

页面应包含：

- API Key 区：DeepSeek API Key 输入框、连接测试、保存/仅本次使用选项、敏感值遮蔽。
- 大纲输入区：标题、章节结构、研究问题、字数/语言/引用格式要求。
- Excel 选择区：选择平台已有 Excel 或上传/指定一个 Excel。
- 生成任务区：开始撰写、进度、当前步骤、失败原因。
- 结果区：综述 Markdown/Word、引用列表、缺失文献提醒、事实核查提示。

重要产品边界：

- API Key 不应明文写入日志。
- 默认可选择“不保存，仅本次使用”。
- 真实 DeepSeek 调用失败时应有 Mock/降级提示。
- P4 只负责页面框架、配置入口和数据流定义；高质量生成策略可放入 P6。

### 4.4 代码与研究资产管理页面

产品目标：

将代码分支管理、依赖安全审计、研究方法、研究工具和可复用经验统一保存，成为个人科研资产库。

页面应包含：

- 代码项目区：项目列表、Git 状态、分支/提交/diff、安全审计报告。
- 研究方法库：方法名称、适用场景、步骤、优缺点、关联文献/项目。
- 研究工具库：工具名称、用途、安装方式、使用说明、注意事项。
- 分析流程库：常用流程模板，例如“文献导入 -> Excel 提炼 -> 综述生成”。
- 资产关联：方法/工具可关联到代码项目、文献、Excel 和综述输出。

P4 应完成资产库的数据结构草案和页面信息架构；P7 再做完整增删改查、搜索和导出。

## 5. 信息架构

建议最终前端路由：

- `/`：控制台首页
- `/journal-tracking`：期刊追踪
- `/folder-analysis`：文件夹文献分析
- `/review-writing`：DeepSeek 综述撰写
- `/research-assets`：代码与研究资产管理
- `/system`：系统配置，作为次级入口保留

建议导航名称：

- 控制台
- 期刊追踪
- 文献分析
- 综述撰写
- 研究资产
- 系统设置

当前已有页面映射：

- `Journals.vue` -> 期刊追踪页面基础
- `Papers.vue` + `Excel` 能力 -> 文件夹文献分析页面基础
- `Reviews.vue` -> DeepSeek 综述撰写页面基础
- `Code.vue` + P1/P2/P3 能力 -> 研究资产页面的代码区基础
- `System.vue` -> API Key、SMTP、模型配置等系统设置基础

## 6. 后端能力分层

P4 建议按以下后端边界改造：

1. 控制台状态聚合
   - 新增或整理 `GET /api/v1/dashboard/overview`。
   - 返回期刊更新数、待分析 PDF 数、最近 Excel、最近综述、代码项目风险摘要、Agent 状态。

2. 文件夹登记与扫描
   - 设计 `POST /api/v1/folders` 登记文件夹。
   - 设计 `GET /api/v1/folders/{id}/files` 查看文件夹内材料。
   - 实际本机扫描由 Agent 白名单任务执行，不开放任意 shell。

3. DeepSeek 配置入口
   - 复用系统配置加密存储。
   - 增加“仅本次使用 API Key”的请求字段设计。
   - 需要测试日志不泄露 API Key。

4. 研究资产模型
   - 预留 `research_methods`、`research_tools`、`research_workflows` 表或等价模型。
   - 资产可关联代码项目、文献、Excel 和综述输出。

5. 桌面启动器
   - PowerShell 启动脚本负责启动 Docker Compose、等待健康检查、打开浏览器。
   - 桌面快捷方式指向该脚本或包装后的启动器。

## 7. P4 关键用户流程

### 流程 A：点击桌面图标进入平台

1. 用户双击桌面图标。
2. 启动器检查 Docker 是否可用。
3. 启动或复用已有服务。
4. 等待 backend healthy。
5. 自动打开 `http://localhost`。
6. 如果未初始化，进入管理员初始化；如果已登录，进入控制台。

### 流程 B：从控制台进入四页面

1. 用户进入首页。
2. 看到四个核心工作入口和最近状态。
3. 点击任一入口进入对应页面。
4. 页面顶部呈现当前任务、最近结果和下一步操作。

### 流程 C：文件夹分析的授权路径

1. 用户在页面输入或选择指定文件夹。
2. 平台创建文件夹扫描任务。
3. Agent 只执行白名单扫描，不执行任意命令。
4. 后端接收文件清单。
5. 用户选择开始批量分析。

## 8. P4 验收标准

P4 完成时应满足：

1. 桌面入口
   - 桌面图标或启动脚本可一键打开平台。
   - 服务未启动时能自动启动。
   - 服务已启动时不重复破坏运行状态。
   - Docker 不可用时有清晰提示。

2. 四页面框架
   - 前端导航显示四个核心页面。
   - 四个页面均可访问。
   - 页面文案符合最终目标。
   - 旧模块能力被合理归并或保留为二级入口。

3. 控制台首页
   - 显示四页面入口。
   - 显示关键状态摘要。
   - 可跳转到每个核心页面。

4. 后端聚合接口
   - 提供控制台概览接口。
   - 返回结构化 Pydantic 响应。
   - 不泄露密钥。

5. 安全边界
   - 不执行任意 PowerShell/CMD。
   - 不自动读取未授权文件夹。
   - 不把 `.env`、真实 PDF、备份和运行数据提交到 Git。

6. 工程验收
   - `pytest -q` 通过。
   - `python -m compileall -q backend agent tests` 通过。
   - `docker compose config --quiet` 通过。
   - `npm run build` 通过。
   - Docker Compose 可启动，backend healthy，frontend HTTP 200。

## 9. P4 之后的阶段承接

P5：

- 完成期刊追踪页深度能力。
- 完成文件夹 PDF 批量分析页。

- 完成 DeepSeek API Key、用户大纲、指定 Excel 到文献综述的生成闭环。

P7：

- 完成代码分支管理和研究方法/工具/流程资产库。
- 完成最终四页面全链路验收、桌面入口验收和 GitHub 最终交付。
