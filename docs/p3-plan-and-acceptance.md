# P3 计划与验收标准

## P3 目标

P3 的目标是在 P1/P2 的只读代码项目检查能力之上，增加依赖安全与许可证合规审计闭环。平台应在不执行上传代码、不安装上传依赖、不自动修改项目文件的前提下，对已解析的依赖清单进行漏洞状态、许可证策略和可归档报告分析。

P3 默认自动化验收不依赖公网或外部密钥。真实 OSV/CVE 联网查询作为显式可选能力：有网络时可使用 OSV API，网络不可用时必须以可重复的本地漏洞数据库完成测试和报告生成。

## P3 交付内容

1. 依赖安全审计模型
   - 新增依赖审计响应模型。
   - 审计结果包含依赖总数、已固定版本数、未固定版本数、高风险依赖数、许可证违规数、漏洞总数、最高严重度和告警列表。
   - 每个依赖返回许可证策略状态、匹配漏洞列表、建议动作和证据来源。

2. 本地可重复漏洞数据库
   - 增加仓库内测试/演示用漏洞数据库 fixture。
   - 数据库按生态、包名和版本匹配，不联网即可稳定复现验收结果。
   - 支持 Python/pip 与 npm 依赖的基础包 URL 归一化。

3. 可选 OSV 查询接口边界
   - 预留 Provider 接口。
   - 默认关闭联网查询。
   - 只有显式配置启用时才查询外部 OSV API。
   - 联网失败时不导致审计失败，应返回 warning 并保留本地审计结果。

4. 许可证策略
   - 内置默认策略：MIT、BSD、Apache、ISC 为允许；GPL、AGPL、LGPL 为需复核或限制；缺失许可证为需复核。
   - 许可证策略结果进入 API、报告和前端页面。
   - 不做法律结论，只提供工程审计提示。

5. 后端 API
   - 新增 `GET /api/v1/code/projects/{id}/security-audit`。
   - 扩展项目检查 Markdown 报告，加入 P3 安全审计章节。
   - 保留 P1/P2 既有接口兼容性。

6. 前端代码页面
   - 新增“安全审计”页签或等价视图。
   - 展示漏洞数量、最高严重度、许可证违规/需复核数量和逐项依赖审计结果。
   - 保持只读，不提供执行、安装或自动修复按钮。

7. 测试与文档
   - 增加单元测试覆盖漏洞匹配、版本比较、许可证策略、OSV 关闭/失败降级。
   - 增加集成测试覆盖上传压缩包后调用安全审计 API。
   - 更新 API 文档、README 和 P3 最终报告。

## 验收标准

P3 最终必须满足：

1. 自动化测试
   - `pytest -q` 全部通过。
   - `python -m compileall -q backend agent tests` 通过。
   - `docker compose config --quiet` 通过。
   - `git diff --check` 通过。

2. 前端构建
   - `npm run build` 成功。
   - 如出现第三方注释或 bundle 体积警告，记录为非阻断事项。

3. P3 功能验收
   - 测试项目中固定版本漏洞依赖能被本地漏洞库命中。
   - 未固定版本依赖被标记为高风险或需固定版本。
   - GPL/AGPL/LGPL 或未知许可证能进入许可证复核/违规统计。
   - 安全审计 API 返回结构化 Pydantic 响应。
   - 检查报告包含安全审计章节。
   - 前端可展示安全审计结果。

4. 安全边界
   - 不执行上传代码。
   - 不安装上传依赖。
   - 默认不联网查询漏洞库。
   - 不读取项目目录外路径。
   - 不把 `.env`、真实 PDF、备份、解析产物、运行数据或外部问题总结文档提交到 GitHub。

5. GitHub 上交
   - P3 代码、测试和仓库内文档提交到本地 Git。
   - P3 成果推送到 `https://github.com/tzh563633/Personal-scientific-research-project-literature.git` 的 `main` 分支。

## P3 不包含内容

1. 不执行真实项目代码。
2. 不自动运行 `npm install`、`pip install` 或其他包管理器。
3. 不提供法律合规结论。
4. 不开启公网 HTTPS 或反向代理。
5. 不进入 P4 或后续阶段，除非用户再次明确确认。
